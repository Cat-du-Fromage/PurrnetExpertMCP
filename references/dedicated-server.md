# PurrNet host vs dedicated — problems to look for

Practical inspiration: skill `edgegap-purrnet` (https://github.com/edgegap/llm-agent-skills/tree/main/skills/edgegap-purrnet), `references/purrnet.md`, and official guide https://edgegap.com/integration/purrnet. Do not copy its configuration without using Edgegap.

## Host ≠ dedicated

A host runs server **and** local client; a dedicated server runs only the server. A `OnSpawned(bool asServer)` method can be called once per role in a host. `if (isHost)` code is usually not suitable for a dedicated.

**Critical anti-bug:** a `[ObserversRpc]` can send a seed, initialize a handle, or create host objects through the local client, but **do not execute its body on the dedicated**. If the server has to run the method, examine `[ObserversRpc(runLocally: true, bufferLast: true)]` and its compatibility with the local version; or explicitly call the server logic in a non-RPC method, then send the replication to the clients. `runLocally` is not necessary for every purely cosmetic RPC.

## Checks before build

1. Identify `NetworkManager` and **Start Server Flags / Start Client Flags**, do not start server/client twice; the client connected by matchmaking should not automatically connect to `127.0.0.1`.
2. Identify transports and ports. UDP PurrNet by default in the Edgegap example: `5000`, while **the Edgegap template uses `7777`**. Never confuse both.
3. Search for `[ObserversRpc]`, `isHost`, `Camera.main`, `AudioSource.Play`, `Input.*` and IU in the entire dedicated path: client-only elements must not cause the headerless server to fail.
4. Verify that players/resources are generated by the server and that the dedicated scenes are included in the build.
5. If manual connection via `NetworkManager.StartClient`, let the asynchronous state transition start; do not cancel the attempt because `clientState` is still `Disconnected` immediately after the call.
6. Do not change ownership rules without analyzing their consequences. A dedicated server does not automatically eliminate client-side abuse.
7. Forecast server shutdown, disconnection, timeout and logs depending on the host. No secret token in client Unity.

## Test de bout en bout

1. A build headless starts without a local client and logs the configured port.
2. Two client builds connect live using the same transport and the right port.
3. An element of the world created **by the server** exists and is consistent for both clients.
4. clients can play, log out, reconnect, and new connections get the required status.
5. Server closure and transport errors are controlled.

To create app/version Docker, allocation, matchmaking and Edgegap lifecycle, load `edgegap-purrnet` if it exists. Do not duplicate the deployment logic in this generalist skill.

### Level of evidence

`edgegap-purrnet` reports real-world tests on its **clean sample** PurrNet with two clients. This does not mean that the examples of `purrnet-expert` have been compiled. Any behavior must be tested in the user's project.
